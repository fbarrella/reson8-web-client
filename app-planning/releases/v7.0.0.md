# 📦 Reson8 Web Client v7.0.0 Release Notes

Phase 7 complete: the app is now installable, self-updating, verified accessible and performant, and tested end to end across real phones, tablets, and desktops on every major browser. This is the launch-ready release — the first version of this client meant to be used for real, not just developed against.

## ✨ New Features & Improvements

- Installable as a real PWA: a distinct, properly-sized icon set, a Chromium in-app "Install Reson8" prompt timed to appear after a successful connection, and an iOS Safari "Tap Share → Add to Home Screen" instructional panel (iOS has no native install prompt to hook into).
- A controlled update flow: when a new version deploys, already-open clients get a persistent "A new version is available" toast rather than silently going stale or interrupting an active voice/chat session — reload happens only when you choose to.
- A "What's New" modal that shows release notes (from GitHub) to returning visitors exactly once per version bump, and never to a genuinely first-ever visitor — ported from the desktop client's own design, rendered as plain text (never parsed HTML/Markdown) for the same security reasons the desktop client established.
- The app icon's unread badge (Badging API) now stays accurate through reconnects, nudges, and disconnects instead of occasionally getting stuck on a stale count in either direction.
- A real Disconnect button in Settings → Application — there was previously no way to leave a connected server from the UI at all.
- Every screen, breakpoint, modal, and admin surface passes a zero-violations accessibility audit (axe-core) — six real defect classes found and fixed along the way, from insufficient color contrast to nested interactive controls to unlabeled sliders.
- Meaningfully faster: the connect screen's initial JavaScript payload dropped roughly in half (260KB → 132KB gzipped) via route-based code splitting, so a first-time visitor isn't downloading the admin console, the full emoji picker, or the voice engine before they've even connected. Lighthouse performance score on mobile went from 69 to 97 out of 100.
- A full real-device testing pass — Android phone, iOS phone, Android tablet, iPad, desktop Chrome/Edge, desktop Firefox, and macOS Safari — confirming the app actually works correctly on real hardware, not just in emulation.
- Deployment is now documented and ready: a recommended static-host path, a working Docker option for self-hosters who want the client running alongside their `reson8` server, and the HTTPS/WSS/CSP requirements spelled out explicitly.

## 🐛 Bug Fixes

- Fixed the Channels tab sometimes showing no channels at all immediately after connecting — a timing race where the app started listening for the server's channel-tree update one step too late on some connections.
- Fixed a false "Insufficient Permissions" alert (toast + sound) that fired for every non-admin user on every connect, even though they hadn't tried to do anything blocked.
- Fixed the Voice tab in the bottom navigation, which had been stuck showing a "Coming in Phase 2" placeholder — it now shows the real, fully-functional voice panel that's been working elsewhere in the app since Phase 2.
