# 📦 Reson8 Web Client v3.0.0 Release Notes

Phase 3 complete: voice gets the fine-grained controls power users rely on (noise gate, per-user volume, global volume), and admins get full touch-first channel lifecycle management (create/rename/delete/NSFW/reorder).

## ✨ New Features & Improvements

- Mic Sensitivity / Noise Gate: threshold-based (-60 to 0 dB) transmission gating with a live level meter, reachable both during an active voice session and standalone from Settings without joining a call — never overrides an explicit manual mute, and is hidden entirely while Push-to-Talk mode is active.
- Per-user local volume (0-200%) and local mute, client-side only and never transmitted to the server, via a shared AudioContext `GainNode` chain per consumer — reachable from a touch-first kebab popover on each occupant row, persisted per user across page reloads.
- Global Voice Chat Volume master attenuator (0-100%) in the new Settings → Audio tab, applying live to every currently-connected participant with no separate Save step — the Audio tab also finally surfaces the Alert Volume and Nudge Volume sliders deferred from Phase 1.
- Channel management for admins: create (name/type/parent category/NSFW), inline rename, and delete (with an accessible confirmation dialog, never a bare `confirm()`) — all reachable via an always-visible kebab menu and a touch long-press, and fully hidden for non-admin accounts both in the UI and by the server's own permission enforcement.
- NSFW text-channel flag, with a once-per-session confirmation gate before a flagged channel's content is shown.
- Channel reordering with two coexisting mechanisms per category (and at the root level): an explicit non-drag Reorder Mode with up/down move buttons as the universally-accessible primary, plus drag handles (via `dnd-kit`, chosen for its touch-sensor support) as a progressive enhancement — both commit atomically in a single server call.
- Client-side permission derivation (`PermissionFlags` bitmask, aggregated from the connected user's own roles) powering all of the above gating, laying the groundwork for Phase 6's full Roles admin surface.

## 🐛 Bug Fixes

None this phase — all Phase 3 work was new capability, not fixes to prior behavior.
